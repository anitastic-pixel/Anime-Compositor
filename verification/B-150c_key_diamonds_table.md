# B-150c: a stretched layer's keys shown and set where they play

Generated by `app/src/main.rs`, module `editing`. Re-run with `cargo test --workspace`.

D-216 has a stretched layer's keys stretch with it, as After Effects' do: a key stored at `k` plays on `in + (k - in) x stretch / 100`. B-150b built that in the picture; the timeline still drew and named keys by their stored frame, so at 200% a key that plays on frame 12 was drawn on frame 8. B-150c is the owner's "Fix key diamonds": the timeline draws each key where it plays, and every request that names a key by its frame - a key added with the playhead, dragged, eased, taken off, a mask's path key - is taken back to the frame it is stored at, by document 20's rule, rounded half away from zero.

Every row calls what the window calls, on `Fixtures/projects/unknown_effect_project.json` with its layer moved to begin on frame 4, and reads back what is stored. The frames were worked out by hand from the rule, not read from the build. The picture is not changed.

## What this does not cover

Whether the diamonds are drawn on the right frame on screen and follow the hand: `verification/B-150_playtest.md`, for a person. The page's rule is checked here as text. A dragged key lands on the nearest frame a stored key can play on, which at 200% is every other frame. The exposure blocks of a stretched drawn layer are still drawn unstretched.
