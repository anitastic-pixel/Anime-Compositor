# P-17: the bug and performance pass over every effect

**Bloom with streaks, Radial Blur and Directional Blur are up to 5.6x faster, and no pixel of any effect moved: all 52 results have the same SHA-256 before and after.** One bug was found and fixed: a project could be saved in a state it could not open again (below).

Asked for by the owner on 2026-09-25, with the batch of seven ("then do a bug/performance pass afterwards of each effect here"). P-16 covered the first six effects; this pass adds the seven new ones to its harness and goes over all thirteen.

## Machine, build and configuration

- CPU: AMD Ryzen 9 9900X, 12 cores, 24 hardware threads
- OS: Microsoft Windows 11 Education, 10.0.26200
- Toolchain: rustc 1.89.0, cargo release profile, `opt-level = 3`
- Pool: rayon's default, one thread per hardware thread
- Harness: `tests/p16_effect_cost.rs`, now with 14 more cases for the seven new effects, run with `cargo test --release --test p16_effect_cost -- --ignored --nocapture`
- Before: commit b59f0e1. After: the commit that carries this page. The same harness, the same day. The after column is the first run after the change; a second run is quoted where the two differ.
- Workload: one effect alone on a 1920x1080 cel, 7 runs each, median reported. Two cels, both generated by the harness: **character**, a figure in flat colours on nothing, about a fifth of the frame showing; **background**, opaque everywhere.

## What changed

Three effects, each still adding exactly the same samples in exactly the same order for every pixel, which is why no bit moved.

- **Directional Blur and Bloom's streaks** (`src/blurs.rs`, `src/bloom.rs`). They used to take one pixel at a time and reach for every sample along its line. They now take one sample step at a time along a whole row, which reads the picture in order, and they skip the part of each row where the step can only land on empty pixels. A character cel is mostly empty, which is where the 3x to 4x comes from. Bloom also leaves out the two end samples of each streak, which weigh nothing. The halo's four blurs are now added into the picture row by row in parallel, in the same order of scale.
- **Radial Blur** (`src/blurs.rs`). A spin used to work a sine and cosine for every sample of every pixel; they are now worked once for each count of samples, by the same sum, and looked up. And a pixel whose whole arc or line stays outside the box round the drawing is not walked, because all its samples are empty and so is its average. That is the 5x on the character; on an opaque plate every path meets the drawing, so only the sine table helps (1.2x to 1.6x).

Every generated table in `verification/` came out byte-identical, except B-19c, which gained the check below. The core suite is 94 of 94 and the app's is 63 of 63.

## The bug audit

**Found and fixed: a project that would not open again after saving.** A project file can key an effect setting (D-68). If it keyed a setting that effect does not have, such as a `radius` on an Exposure, opening it took those keys as the effect's, and saving wrote the setting back nested inside itself. The saved file was then refused on opening: "part of it does not match the project format". Now keys on a setting the effect does not have are left in the file exactly as written, as any other setting the effect does not have already was. `verification/B-19c_fxkey_table.md` gains the row "FX-FXK-001 with keys on a radius, which exposure does not have, saves them as written and opens again": `the same, opens`, 48 of 48. With the fix taken out, the row reads `differs, refused` and the table fails.

**Checked and found right:**

- Every setting that can be keyed on any of the thirteen effects is one the file reader takes keys for. There are 15 names, and none is missing.
- The effect-result cache (P-11) is keyed by every setting, the words and colours included. Changing Match By, Keep or Streaks can never show a stale picture.
- A draft preview scales the settings that are distances: the directional blur's length, the line width, and the bloom's radius and length. It leaves colour distances and angles alone.
- Every effect on a 1x1 layer runs, and every number it gives is finite.

**Found and left, with the reason:**

- Gaussian Blur, Directional Blur, Line Width and Radial Blur stop the program on a layer 0 pixels wide. The Gaussian Blur already did this before the batch. Nothing can hand them one: a composition of width 0 is refused, a draft size rounds up to at least 1, and a picture always has pixels.
- Bloom's stated reach, used only by its table's "How far it reaches" row, is the full reach even when intensity is 0 or nothing is bright enough. In those cases the render grows the layer by nothing. The render uses its own figure, so no frame is affected.

## What was not made faster, and why

- **Bloom's streaks on an opaque plate, about 340 ms for a star of length 60.** Everything is lit, so nothing can be skipped. Four lines of 121 samples at every pixel is the arithmetic itself. A running sum along each line would be much faster, but it adds the samples in a different order and so moves bits. That makes it a decision for its own fixtures, not a speed-up.
- **Radial Blur on an opaque plate, 160 to 185 ms.** Up to 256 samples a pixel along curves. A polar resampling is the next step, and it too changes the arithmetic.
- **Directional Blur 100 on an opaque plate, 144 ms.** The same reasoning as for the streaks: a running sum would change the bits.
- **Line Width 10, 62 ms on the character.** Each edge pixel searches a disc. A distance transform is the upgrade if wider lines are wanted often.
- **Line Recolour, Select Colour, Colour Key**: 2 to 6 ms already.
- **Selective Colour Blur**: left as P-16 decided.
